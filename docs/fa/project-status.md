# وضعیت پروژه‌ها

افزونهٔ project-status بالای ورودی یک ردیف برای هر پروژه نشان می‌دهد: تعداد کارهای انجام‌شده، کار بعدی و مرحلهٔ آن، فایل‌های تغییرکرده و کامیت‌های جلوتر از upstream. پروژهٔ نشست فعلی اول نمایش داده می‌شود.

## استفاده و فرمان‌ها

فرمان `/projects` نوار را باز یا بسته می‌کند؛ نوار در ابتدا پنهان است. دکمهٔ sync یک پیام کاربر می‌فرستد. برای پروژهٔ فعلی متن همان عبارت تنظیم‌شده است؛ برای پروژهٔ دیگر، نام و مسیر پروژه هم افزوده می‌شود. پس از تمرکز روی نوار، کلیدهای نمایش‌داده‌شدهٔ ۱ تا ۹ نیز قابل استفاده‌اند. خود افزونه عملیات همگام‌سازی یا پوش را اجرا نمی‌کند؛ رفتار نهایی به دستورهای دستیار بستگی دارد.

## تنظیمات

| متغیر محیطی | کاربرد و پیش‌فرض |
| --- | --- |
| `CLAUDE_MODS_SYNC_PHRASE` | متن پیام؛ پیش‌فرض sync؛ مقدار خالی نیز پیش‌فرض را فعال می‌کند |
| `CLAUDE_MODS_PROJECTS_DIR` | پوشهٔ والد پروژه‌ها؛ پیش‌فرض ~/projects |
| `CLAUDE_MODS_PROJECTS_FILE` | فایل JSON اختیاری پروژه‌ها؛ پیش‌فرض ندارد |

در مسیرهای تنظیم‌شده، پیشوند ~/ به پوشهٔ خانه گسترش می‌یابد. متغیرها را پیش از شروع Claude تنظیم کنید:

</div>

```sh
export CLAUDE_MODS_PROJECTS_DIR=~/projects
export CLAUDE_MODS_SYNC_PHRASE='Update project status'
```

<div dir="rtl">

فایل اختیاری باید آرایه‌ای از شناسه، نام و مسیر نسبی به پوشهٔ والد باشد:

</div>

```json
[{"id":"demo","name":"Demo","dir":"demo"}]
```

## روش کار و مثال

پوشه‌های فرزند مستقیم که STATUS.md دارند، خودکار به فهرست افزوده می‌شوند؛ جست‌وجو بازگشتی نیست. فقط چک‌باکس‌های بخش دقیق `## Tasks` شمرده می‌شوند. تیتر سطح سوم نام مرحله را مشخص می‌کند:

</div>

```markdown
## Tasks
### Build
- [x] Read requirements
- [ ] Implement parser
```

<div dir="rtl">

در شروع نشست، پایان هر نوبت، هر ۶۰ ثانیه و هنگام باز کردن نوار، اطلاعات تازه می‌شود. نبود فایل فهرست یا خطای خواندن آن نادیده گرفته می‌شود؛ ساختار دادهٔ آن باید معتبر باشد. پرس‌وجوهای گیت مهلت ۱۰ثانیه‌ای دارند؛ دادهٔ ناموجود یا upstream تعریف‌نشده ممکن است صفر نمایش داده شود.
